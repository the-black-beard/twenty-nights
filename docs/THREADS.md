# Threads

Work on Twenty Nights is split into threads — one conversation each, named so
that the list sorts into the order the work happens in.

## The prefix

```
TN-<phase><number> · <short name>
```

`TN` for the project, a letter for the phase, a number within it. Alphabetical
order is chronological order, so a sorted list of sessions reads as a plan.

| Phase | What it covers |
|-------|----------------|
| **A** | Foundation — repo, docs, tooling, CI |
| **B** | Finalise v1 — the current feedback round, shipped to friends |
| **C** | Prototypes — throwaway code answering one design question |
| **D** | The Nether — the maze level and the hammer |
| **E** | The Swarm — the finale and the ending |

## Picking up TN-A2

Everything TN-A1 produced is committed. Start a fresh session in this directory,
read `README.md` then `CONTEXT.md`, and carry on from here:

1. **Authenticate the GitHub CLI.** `gh` 2.102 is installed; it has never been
   logged in. `gh auth login` is interactive, so a human has to run it.
2. **Create the repo and push.** The account is `the-black-beard`, a personal
   user account — GitHub has no GitLab-style groups, only organisations, and an
   organisation for two people is administration with no benefit. Repos sit
   directly under the user and can be moved into an organisation later for free.
   `gh repo create the-black-beard/twenty-nights --private --source=. --push`
3. **Settle private versus public** — the one real decision waiting. Public
   unlocks GitHub Pages on the free tier, which would give the game a permanent
   public URL with no sign-in, solving the sharing problem properly rather than
   through artifact links. The repo holds no secrets and the account is
   pseudonymous. Against: it is a child's project, published under a name that
   could be connected to him. Ask before flipping it.
4. **Add the git guardrails** (`git-guardrails-claude-code`) before any
   automated committing and pushing starts, not after.

Two things done in TN-A1 worth knowing: the repo-local git identity is
`the-black-beard@users.noreply.github.com`, deliberately not the work address
configured globally; and everything under `assets/`, `dist/` and
`Twenty Nights.html` is generated by `node tools/build.js` and untracked, which
was verified by wiping and rebuilding them byte-for-byte.

## Rules

- **One thread, one phase.** Grilling, spec and tickets stay in a single
  unbroken conversation so they build on the same thinking. Each implementation
  ticket then starts fresh from the ticket.
- **A thread ends when its output is in the repo.** If something is worth
  carrying to the next thread, it belongs in `CONTEXT.md`, an ADR, or a ticket —
  not in conversation history.
- **Prototypes get their own directory**, outside this repo, and hand their
  findings back as a written file.

## Branches and tags

| Pattern | Meaning |
|---------|---------|
| `main` | What friends are playing. Only merged after someone has actually played it. |
| `try/<idea>` | One design variant, built to be played and compared against another. |
| `tn-<phase><n>/<slug>` | Ticket work. |
| `archive/<idea>` *(tag)* | A variant that lost. Kept forever, costs nothing, out of the way. |

A rejected idea is tagged, never deleted. When two variants are in play, publish
each as its own artifact and let ig-b-dynamix play both before anything is merged.
